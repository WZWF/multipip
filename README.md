# 多窗播放 Multi-PiP (v0.12.3)

一个面向 Chrome / Edge / Brave（Chromium 116+）的视频多窗与画中画增强扩展：支持将任意网页（B 站、YouTube、腾讯视频、爱奇艺、优酷、各类网课/公开课、直播等）的视频弹出为置顶窗口，提供**跨标签页多视频同窗合并（多视频坞）**与**无限多开的真·无边框置顶窗**。

---

## 核心特性

1. **全网通用的高画质本地 WebRTC 直推（Local WebRTC Loopback HQ）**
   - 只要网页里有 `<video>` 元素，即可通过浏览器原生满帧捕获 + 本机内存级 WebRTC 回环通道（`iceServers: []` + `127.0.0.1` 直连，零外网请求、免疫防火墙/代理虚拟网卡 mDNS 拦截、延迟 < 30ms）将视频推送至跨标签页置顶坞或原生无边框窗。
   - **蓝光级原画质直通**：自动注入高码率 SDP（最高 `35Mbps`）并锁定 `1:1` 原始分辨率（`maintain-resolution`），60fps 高清画面零缩水；原页面保留原生音轨播放（无二次重编码失真、无双重声音），小窗控件实时反向控制原视频。

2. **五种置顶模式 + 自动降级兜底**

   | 模式 | 窗口形态 | 置顶 | 数量限制 | 适用场景 |
   | :--- | :--- | :---: | :---: | :--- |
   | **原生小窗**（`dock`） | 多视频置顶坞：无边框置顶窗，内置 5 种布局与独立卡片控件 | 是 | 全局 1 窗（可合并多个同页/跨标签页视频） | 多路比赛/直播同屏、边看网课边看资料 |
   | **原生画中画**（`native`） | 浏览器自带极简画中画窗 | 是 | 全局 1 窗 | 单视频极简置顶观看 |
   | **无边框窗**（`companion`） | 原生伴侣程序：无标题栏、无地址栏、支持一键全屏平铺与外挂字幕 | 是 | **无限制（可无限多开）** | 多窗口自由摆放、跨屏排布、挂载本地字幕 |
   | **原生拆窗**（`solo`） | 把整个标签页挑进 Chrome popup 小窗，页面用 CSS 铺满，由常驻 Win32 宿主置顶并裁掉工具栏 | 是 | **无限制（一窗一视频）** | **多开看直播/网课/监控，要求零画质损耗、零重编码、支持 DRM** |
   | **独立窗口**（`window`） | 浏览器 `window.open` 弹窗（当页面不支持 PiP 时自动兜底） | 否 | 不限（带地址栏） | HTTP 页面或受限环境自动降级 |

3. **多视频坞（原生小窗）交互**
   - **五种布局一键切换**：堆叠（按比例）/ 宫格 / 大+左 / 大+右 / **自由布局**（任意拖拽位置与无级缩放大小，按窗口比例记忆位置）。
   - **窗口与卡片全屏**：支持整个坞窗口一键全屏或小/中/大三档缩放；支持单张视频卡片在坞内全屏独占（其余卡片自动暂停，退出后恢复）。
   - **完整控制条**：悬停卡片浮现播放/暂停、进度条、音量、**倍速循环（0.5x ~ 2.0x）**、全屏独占与召回按钮。

4. **无边框原生伴侣窗（免 Python、零配置修改）**
   - **一键多窗排版**：面板内置「均分平铺」「左右对分」「上分下独」「左大右辅」四种全屏自动排布。
   - **本地外挂字幕**：支持点击挂载或直接将 `.srt` / `.vtt` 字幕文件拖入无边框窗口。
   - **快捷键与极速倍速**：支持 `空格` 播放/暂停、`←/→` 快退/快进 5 秒、**长按鼠标右键（或长按 `→` 右方向键）触发 2.5x 倍速冲刺（松开恢复原倍速）**，以及随时切换窗口置顶状态。

5. **克制无感、零打扰的页面交互**
   - **无视频页 100% 隐形**：仅在检测到有效视频的顶层主页面显示右侧贴边微露胶囊（自动屏蔽无视频普通网页、内嵌 `iframe` 及小弹窗），移入自动滑出，并支持点击 `×` 一键隐藏。
   - **右上角角落精准唤醒**：平时鼠标在视频中央观看、暂停或拖进度条时画面纯净无遮挡；仅将鼠标移至**视频画面右上角小区域**时才会柔和浮现「独立播放」按钮，移开即刻消失（全屏及小缩略图自动免打扰）。

## 快速安装（零配置修改，即装即用）

本项目已内置固定扩展公钥与相对路径宿主清单，**克隆或下载解压到任意电脑、任意盘符均无需修改任何配置文件**。

### 第一步：获取项目
- **方式 A（Git 克隆）**：
  ```bash
  git clone git@github.com:WZWF/multipip.git
  # 或者使用 HTTPS:
  git clone https://github.com/WZWF/multipip.git
  ```
- **方式 B（压缩包下载）**：
  在 [GitHub 仓库页面](https://github.com/WZWF/multipip) 点击右上角绿色 `Code` -> `Download ZIP`，解压到本地任意固定目录（注意：安装后请勿移动该文件夹）。

### 第二步：在浏览器中加载扩展
1. 打开 Chrome 访问 `chrome://extensions/`（Edge 访问 `edge://extensions/`）。
2. 开启右上角的 **「开发者模式」**。
3. 点击左上角 **「加载已解压的扩展程序」**，选择解压后的项目根目录（包含 `manifest.json` 的文件夹），或直接将该文件夹拖入扩展管理页面。

### 第三步：（可选）一键开启「无边框原生窗」
> 如果只需要使用「原生小窗（多视频坞）」和「原生画中画」，跳过此步即可。

1. 进入项目下的 `companion` 文件夹，**双击运行 `register_host.bat`**（无需安装 Python，无需管理员权限，无需手动输入扩展 ID）。
2. 回到浏览器扩展管理页（`chrome://extensions/`），点击本扩展卡片上的 **刷新** 图标即可生效。
3. *（如需卸载伴侣注册表项，双击运行 `companion/unregister_host.bat` 即可。）*

## 使用指南

1. 打开任意包含视频的网页。
2. **弹出视频**：
   - 将鼠标移至**视频画面右上角角落**，点击浮现的 **「独立播放」** 按钮（平时在视频中间移动鼠标不遮挡画面）；
   - 或将鼠标移至网页右侧边缘滑出 **「🎬 多窗播放」** 胶囊按钮（仅含视频的主页面显示），在面板中选择模式并点击对应视频的 **「弹出」**。
3. **多视频合并 / 屏幕贴靠与排版**：
   - **原生小窗模式**：在标签页 A 弹出第一个视频后，切换到标签页 B 再次点击弹出，视频 B 会自动合并进同一个置顶小窗中。小窗顶部控制栏新增 **「⊞ 分屏」** 下拉面板，支持一键将小窗贴靠至**左半屏 / 右半屏 / 上下半屏 / 四角 1/4 屏**。
   - **无边框窗模式**：切换到「无边框窗」后可连续弹出多个独立置顶窗口，点击右下角面板中的 **「多窗排版」** 即可一键进行**均分网格 / 左右对分 / 左半 / 右半 / 右上1/4 / 右下1/4** 等智能屏幕贴靠。
   - **拆窗模式**：每个视频一个独立标签页窗口，面板里出现 **「拆窗窗口」** 一行，可用 **宫格平铺 / 横排** 一键把当前所有拆窗窗口铺满屏幕；宿主侧拖动松手时还会自动吸附屏幕边缘。
4. **全局倍速快捷键**：按 `Alt + Shift + S` 可快速循环切换当前活动视频的播放倍速（`0.5x` ~ `2.0x`）。
5. **召回视频**：按 `Esc`、点击小窗右上角 `×`、点击原网页上的占位提示条，或在右下角面板中点击「召回」，即可将视频无缝放回原网页。

## 目录结构

```text
multipip/
├── manifest.json                 # MV3 扩展清单（含固定公钥 key、nativeMessaging、快捷键 Alt+Shift+S）
├── content.js                    # 核心逻辑：多视频坞(5种布局/自由缩放) / 本地 WebRTC 跨标签推流 / 面板与排版
├── background.js                 # Service Worker：坞归属管理 + WebRTC 信令/控制中继 + 伴侣进程桥接
├── popup.html                    # 浏览器工具栏图标弹窗说明
├── icons/                        # 16 / 48 / 128 PNG 扩展图标
├── host/winhost/                 # 原生拆窗置顶宿主源码（Go，约 200 行，单文件 exe 约 1.7MB）
│   ├── main.go                   # Native Messaging 协议 + EnumWindows 认领窗口 + SetWindowPos 置顶
│   └── build.bat                 # go build 到 companion/dist/multipip_winhost/
└── companion/                    # 原生伴侣（免 Python、零配置修改）
    ├── com.multipip.host.json    # 无边框窗宿主清单（WebView2 方案）
    ├── com.multipip.winhost.json # 原生拆窗置顶宿主清单（Win32 方案）
    ├── register_host.bat         # 双击一键写入当前用户注册表（支持 Chrome / Edge / Brave / Chromium）
    ├── unregister_host.bat       # 双击一键清理注册表项
    └── dist/                     # multipip_host/（WebView2）+ multipip_winhost/（Win32 置顶）
```

## 常见问题与限制

- **低配置电脑（CPU 较弱、核显、8G 内存）怎么使用最省资源？**  
  - **首推「原生画中画」模式**：单视频弹出时，在面板切换为「原生画中画」或直接在视频右上角点击弹出。此模式直接调用 Windows 底层 Direct3D 硬件 Overlay 零拷贝图层，**CPU 占用率接近 0%，内存 0MB 额外占用，不发热不掉帧**。
  - **同页面多视频合并「原生小窗」**：同页视频直接采用 DOM 节点无损迁移，完全不需要额外编码，轻快省电。
  - 最新版本已将跨标签页 WebRTC 回环从 35Mbps 过饱和软编改为：**用 `setCodecPreferences` 优先 H.264 硬编（Windows 核显 / NVENC / AMF）+ 编码分辨率对齐小窗实际显示尺寸 + 按路数分档限码限帧**，大幅降低普通办公本的 CPU 与风扇负担。
- **某些网站（如嵌套在 iframe 播放器内）弹出报错 `only allow for a top-level browsing context`？**  
  已全面防御修复。W3C 规范禁止子 frame 直接调用 Document PiP，扩展会自动识别并在子框架内平滑降级至系统原生画中画，保证任何嵌入式视频都能秒弹成功且不再报错。
- **为什么有的视频（如 Netflix）提示无法捕获画面流？**  
  受硬件级 DRM（Widevine L1 等）保护的加密流媒体在浏览器底层禁止 `captureStream()`，此时请改用浏览器自带的「原生画中画」模式。
- **跨标签页合并或使用无边框窗时，原网页可以关掉吗？**  
  不能关闭源标签页（可以切换到后台或其他标签页）。画面流与音频由源标签页实时解码提供，扩展已自动阻止后台标签页被浏览器休眠暂停。
- **「原生拆窗」模式和「无边框窗」有什么区别？**
  - **原生拆窗**：把视频所在的**整个标签页**原样搬进一个置顶 popup 窗口，页面自己渲染，**零重编码、零拷贝、画质与帧率 100% 原生、支持 DRM**，多开 4 路等价于开 4 个普通标签页（各自硬件解码）。宿主会用 `SetWindowRgn` 裁掉 Chrome 的标题/地址栏条，做成真无边框（工具条上有 ✂ 开关可随时关掉）；裁边后窗口由工具条上的 ⣿ 负责拖动（松手自动吸附屏幕边缘）、◢ 负责等比缩放。隔离时会**保留播放控制条/进度条**（按类名与位置识别，抬到铺满的视频之上）；若某个站点的控制条仍被藏掉，点工具条上的 ◉「已隐藏页面」关掉隐藏即可。若某些站点的页面内容遮不干净，点工具条上的 ⤓「接管画面」，扩展会把 `<video>` 直接搬进全屏舞台（同文档零拷贝，不重载不编码），并按站点记住这个选择。代价是标签页被搬走，不能同时在原页刷评论。
  - **无边框窗**：`captureStream → 本地 WebRTC` 再编码到 WebView2，**没有边栏**、支持外挂字幕与多窗排版，但每路都有一次重编码（已优化为 H.264 硬编 + 对齐显示尺寸），且 DRM 视频无法捕获。
  - 需要 **真·无边框** 或要挂字幕 → 用无边框窗；需要 **多开不卡 + 原画质 + DRM** → 用原生拆窗。
- **为什么小窗调音量不会让原页面也出声？** 音频只走一条路：走 WebRTC 的模式（跨标签坞 / 无边框伴侣窗）音频随流进入小窗播放，源页统一静音；同页 adopt（坞窗直连 / 拆窗）不搬家也不静音，由源页自己出声。任何控制指令都只改音量、不动静音状态，所以不会出现双声。
- **原生拆窗需要装什么？** 复用同一套安装流程：双击 `companion/register_host.bat` 会同时注册两个宿主（`com.multipip.host` 与 `com.multipip.winhost`），然后在 `chrome://extensions/` 刷新扩展即可。若只需要置顶、不关心字幕，可以只用拆窗模式。
- **原生拆窗的已知限制**：裁边后窗口的关闭要走工具条上的「召回原窗口」（Chrome 自带的 × 已被切掉，`Alt+F4` 仍可用）；无边框伴侣窗（WebView2 方案）被最小化时还不会自动暂停编码，因为那个宿主是编译好的 exe、没有上报可见性的命令。
- **移动了项目文件夹位置后怎么办？**  
  如果移动了项目目录，请在浏览器 `chrome://extensions/` 中重新加载新路径，并重新双击一次 `companion/register_host.bat`。

## 性能诊断（WebRTC 遥测）

多开卡顿时，先别改参数，先确认卡在哪一层。`content.js` 内置了一个默认关闭、关闭时零开销的诊断模块。

**开启**（在视频所在页面的 DevTools 控制台执行，然后刷新页面）：

```js
localStorage.setItem('__multipip__:stats', '1');
```

**读取**（弹出小窗后，控制台每 2 秒打印一行，或手动汇总）：

```js
mpStats.report();          // 每个连接的均值 + 自动结论
copy(mpStats.csv());       // 导出 CSV 贴到表格里对比改动前后
mpStats.off();             // 关闭
```

> 上面三行需要把 DevTools 控制台左上角的上下文从 `top` 切到扩展（内容脚本）才能用。
> 不想切上下文的话，在**默认控制台**里用事件桥接，效果一样：
>
> ```js
> document.dispatchEvent(new CustomEvent('mp-stats', { detail: 'report' }));
> document.dispatchEvent(new CustomEvent('mp-stats', { detail: 'csv' }));
> copy(document.documentElement.dataset.mpStatsCsv);   // 导出 CSV
> document.dispatchEvent(new CustomEvent('mp-stats', { detail: 'off' }));
> ```

打印内容示例：

```
[mp-stats] companion#3 OUT 1280x720@29.9 | src 1920x1080@29.9 | 3189kbps | 4ms/f | codec=H264 | MediaFoundation | limit=none | down=1.5 cap=2500k fps<25 framerate H264
```

**怎么看结论**：

| 现象 | 含义 | 该改哪里 |
| :--- | :--- | :--- |
| `src` 帧率远低于源视频帧率（如 8fps） | 源端根本没吐帧，多半是后台标签页节能降帧 | 改静音策略 / 别用 WebRTC 走拆窗；调编码参数**无效** |
| `src` 正常但 `OUT` 帧率只有一半 | 编码侧跟不上 | 降 `scaleResolutionDownBy`、限帧、优先硬编 H.264 |
| `encoder` 是 `libvpx` / `libaom` / `openh264` | 走了 CPU 软编 | `setCodecPreferences` 优先 H.264（别手改 SDP） |
| `ms/f` > 10（健康 < 6ms） | 编码器过载 | 降分辨率 / 降帧率 |
| `limit=cpu` | 编码 CPU 饱和 | 同上 |
| `IN` 侧帧率低但 `OUT` 正常 | 接收侧解码或渲染瓶颈 | 检查 WebView2 / 小窗渲染 |
| 出现 `\| TAB-HIDDEN` 且 `src` 帧率塌到个位数 | 源标签页切后台后被 Chrome 降帧 | 见下面「源端后台降帧」 |

### 源端后台降帧（默认关闭，需实测再开）

原视频被 `muted=true` 且标签页不可见时，Chrome 可能把它当成"无声的后台视频"把解码降到 1~5fps，`captureStream` 抓到的就是幻灯片。可以在视频页控制台切换静音策略（改完刷新页面）：

```js
localStorage.setItem('__multipip__:audioKeepAlive', 'gain'); // WebAudio 零增益
localStorage.setItem('__multipip__:audioKeepAlive', 'tiny'); // 保留音量 0.001，Chrome 认为仍在出声
localStorage.removeItem('__multipip__:audioKeepAlive');      // 关闭（默认）
```

用 `mpStats.report()` 对比切换前后的 `srcAvg` 帧率：如果 `src` 本来就接近源帧率，就保持关闭（WebAudio 接管音频有让 DRM 站点或 captureStream 音轨失效的风险）。
